# Cognitive Load Theory (Sweller, 1988)

## Citation
- Sweller, J. (1988). Cognitive load during problem solving: Effects on learning. *Cognitive Science*, 12(2), 257–285. https://doi.org/10.1207/s15516709cog1202_4
- Sweller, J., van Merriënboer, J. J. G., & Paas, F. (1998). Cognitive architecture and instructional design. *Educational Psychology Review*, 10, 251–296.

## Core idea
Human working memory is severely limited when processing novel information. Effective learning and problem solving depend on how cognitive resources are allocated. Instruction and interface design should work with these limits rather than against them.

## Types of cognitive load
- **Intrinsic load**: effort required by the inherent complexity of the material or task (number of interacting elements that must be understood together). It can be managed by sequencing, simplifying steps, or isolating elements, but not eliminated without changing the task.
- **Extraneous load**: effort imposed by poor presentation or unnecessary elements (clutter, irrelevant visuals, confusing labels, split attention, redundant information). This is "wasted" effort and should be minimized.
- **Germane load**: effort devoted to building and automating schemas/mental models. Good design frees capacity from extraneous load so it can support understanding.

> Note: Later refinements of the theory treat germane processing as the working-memory resources devoted to dealing with intrinsic complexity rather than a fully separate additive source, but the practical design implication remains: cut waste, manage complexity, support understanding.

## UX implications (distinct to this principle)
- **Eliminate extraneous load**: remove decorative or irrelevant elements, redundant copy, ambiguous labels, and visual noise that do not help the user complete the task.
- **Manage intrinsic load**: break complex tasks into smaller, ordered steps; present only what is needed for the current step; use progressive disclosure for advanced detail.
- **Reduce split attention**: keep related information close together (labels with fields, instructions with actions) so users do not have to mentally integrate separated pieces.
- **Favor clarity over density**: prefer a calm, focused layout over showing everything at once.

## Actionable checks
- [ ] Can any element be removed without harming task completion? If yes, remove it.
- [ ] Is each screen or view focused on a single primary purpose?
- [ ] Are complex flows split into step-by-step screens instead of one dense form/page?
- [ ] Are instructions and controls co-located and unambiguous?
- [ ] Is advanced/optional information hidden until needed?
